# infra/iam-casdoor 的设计

本页写这个组件为什么这样设计：术语、拥有的数据、规则、接口、实现状态与未决问题。写给要修改它的人与 AI。怎样使用、部署与配置在 `BRICKKIT.md`；代码在哪、怎样构建与测试、设计取舍在 `AGENTS.md`；身份族共用的契约在装配项目的 `contracts/infra/iam`；规则全文在装配项目的安全 02（可信身份）、03（外部来源与水位）、11（身份成员的切换）、协议 15（证据）、协议 19（密钥）、协议 20（登录与会话）与组件协议第 08 章。

## 边界

身份族的 Casdoor 成员：浏览器登录与会话、访问令牌的签发、签名公钥，把 Casdoor 账号绑定到平台主体。所有部署都需要一个身份成员；选 Casdoor 作为身份提供方时用它。

| 不在这里 | 归谁 |
| --- | --- |
| 授权（角色、部门、能做什么） | `infra/authz` 的视图；令牌只带身份 |
| 员工、任职 | `mdm/employee`（入职事件开通账号是以后的事） |
| 账号本身的存储与认证 | Casdoor（基础资源，不是组件） |

## 术语

| 业务叫法 | 定义 | 代码标识符 |
| --- | --- | --- |
| 平台主体 | 部署内稳定的身份（UUIDv7）；令牌的 `sub`；Casdoor 的用户 ID 不离开本组件 | `PrincipalRef`、`iam_account` |
| 会话 | 浏览器登录后在服务端保存的会话；浏览器只拿到 `HttpOnly`、`SameSite=Lax` 的会话 Cookie，库里只存它的摘要 | `iam_session` |
| 登录中的请求 | 授权码加 PKCE 的一次登录；状态参数只存摘要、只能用一次 | `iam_login` |
| 访问令牌 | 本组件签名的短期令牌（`at+jwt`），按会话换取；令牌类型不能互换 | `tokens.go` |
| 签名密钥 | Ed25519；`kid` 是 RFC 7638 指纹；另备一把下一把密钥，轮换时 SDK 重读 | `IAM_SIGNING_KEY_FILE`、`IAM_SIGNING_KEY_NEXT_FILE` |
| 开发换取 | 用户名与密码换访问令牌，只给种子与自动化测试；只在 `IAM_DEV_EXCHANGE` 为真时存在 | `/api/iam/dev/token`（A101） |

## 拥有的数据

| 表 | 内容 |
| --- | --- |
| `iam_account` | Casdoor 账号与平台主体的绑定 |
| `iam_login` | 登录中的请求（状态的摘要、PKCE、返回地址），用一次 |
| `iam_session` | 会话（Cookie 秘密的摘要、空闲与绝对期限） |

签名密钥是挂载的文件，不在库里。以后加：服务令牌的签发记录（部署选这条路线时；默认的服务身份是部署信任域签发的证书）、外部身份源的绑定、移动端的刷新令牌。

## 规则

- 令牌由本组件签名，不转发 Casdoor 的令牌：`sub` 是平台主体；令牌的类型与有效期由协议定，换身份成员时组件看到的令牌形状不变（安全 11）。
- 令牌只带身份，不带角色或部门。
- `return_to` 只能是站内路径（否则登录成了开放跳转）。
- 开发换取的路由只在打开时注册；上线检查确认它关着，且 Casdoor 里没有开着密码授权的客户端。
- 对 Casdoor 的调用经 SDK 的调用策略（截止时间、重试、熔断）；Casdoor 拒绝授权时答 `TOKEN_INVALID`，原因不对外显示。
- （设计，本版未做）登出与停用向边缘推送失效，最坏由令牌有效期界定；刷新在会话锁内只做一次，旧刷新令牌再次使用时撤销整串。

**作为授权的外部来源**（设计，安全 03）：Casdoor 给不出可靠的变更序号（操作记录连失败的请求也写，webhook 不带序号、约每 30 秒批量发出），所以正确性靠定期的全量状态比较，webhook 只用来更快地发现。收到补取请求时先向产品拉取截至此刻的账号变更，写入发件表后再写回声，拉取失败时不写回声；另按 `P_pull`（起始 1 分钟）定期拉取。停用由本组件记证据（协议 15），以自己记录的停用为准：只有产品坐标中晚于本地记录的启用才认作重新启用，否则判为产品回退，重新停用并告警。本组件是水位来源（协议 02）；高可用部署中全部写入同步提交（D66，协议 15）。整套恢复后结束恢复前创建的全部会话，撤销刷新令牌，按证据强制凭据收紧过的主体重设密码与 MFA。

## 接口

设计上的命令：登录回调、会话的令牌签发（边缘按会话缓存，D61）与失效推送、登出；服务令牌签发（部署选用这条路线时）；公钥集合；补取（水位探测：只对声明订阅的服务身份开放，返回到回声为止的变更，协议 02 的来源水位）。本版的路由全部是公开路由（登录之前没有令牌），由本组件自己保护：`GET /api/iam/login`、`GET /api/iam/callback`、`POST /api/iam/session/token`（按会话换访问令牌）、`POST /api/iam/logout`、`GET /api/iam/jwks`；开发环境另有 `POST /api/iam/dev/token`。没有系统面。

## 事件（设计）

账号停用、会话撤销；水位回声（作为授权的内部来源，安全 03）。本版还没有事件，见“实现状态”。

## 依赖

Casdoor（基础资源）与数据库（必需）；不调用其他组件。可选：外部身份源（按客户）；`mdm/employee`（只经事件，开通账号，以后）；`infra/audit`（兼任证据存储，停用的意图，以后）。

## 实现状态

实验第 5 步的范围：浏览器登录、会话、访问令牌、JWKS、开发换取。没有做的：账号停用的拉取与事件 `infra.iam.account_status_changed.v1`；补取与水位回声；边缘的会话缓存插件与失效推送；移动端的刷新令牌；服务令牌。

## 部署与替换

边缘缓存会话令牌，本组件不在每个请求的同步路径上；短暂重启只影响新登录与令牌续期。作为授权的内部来源，本组件或身份产品停机超过 `D_src_high`（起始 60 秒）时高风险操作暂停（D64）。与 `infra/iam-keycloak`、通用 OIDC 适配互为单选替换（安全 11）。单跑或外壳。适用安全 02、08、19、20。

## 验证故事

| 故事 | 本版 |
| --- | --- |
| 多标签页同时刷新只刷新一次 | 刷新令牌本版不做 |
| 停用账号后失效推送到达即拒绝浏览器请求，推送丢失时不晚于令牌有效期 | 停用与推送本版不做 |
| 在 Casdoor 控制台直接停用账号，补取或定期拉取时被拉取并记证据 | 拉取本版不做 |
| 签名密钥泄露后立即切换到备用密钥 | 备用密钥与轮换（单元测试） |

## 未决问题

- 边缘的会话缓存与失效推送：随附的插件还是旁挂进程（代表部署实验）。
- 账号停用的拉取间隔与全量比较的成本。
